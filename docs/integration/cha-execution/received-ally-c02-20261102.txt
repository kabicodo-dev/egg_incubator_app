3. START, START_BATCH and CONFIRM
Provisional: has START, STOP, STATUS. It has no START_BATCH and no CONFIRM.
Firmware: has a numeric START ({"id":301,"cmd":"START","batch_id":7001}), with ACK start_received followed later by a running frame with status:"running". It has no START_BATCH, no CONFIRM, and no STOP.
Supersession: the implemented numeric START is the only START that exists in firmware/fixtures/tests. START_BATCH/CONFIRM is not implemented and is not in the C-02 files; it should be explicitly marked superseded/not selected. Do not alias either vocabulary onto the other.
Replacement: I have not issued a corrected contract that replaces the provisional version. The existing docs/ally_response_2026-11-01.md is a firmware review/response, not a replacement wire contract. The corrected C-02 should be one jointly reviewed revision; my input is the compatibility findings above and the implemented numeric catalog.
4. Disposition
REQUEST CHANGES. I do not accept the provisional contract as firmware-compatible.

Exact shared-wire acceptance of provisional v1 is BLOCKED on the same fundamental mismatch Kath identified: the provisional type/command_id/payload.action family is not the implemented id/cmd/START family, and the firmware lacks the required identities, timestamps, status frame, error frame, STOP, and RX capacity.

C-02 itself is not blocked. A corrected revision can be reviewed if it does one of these explicitly:

Adopt the implemented numeric catalog as interim v1, documenting its limitations: numeric id/batch_id, flat telemetry, ACK/RUNNING/event, no STOP, no status-state frame, no RTC, no device_id/boot_id/sample_id/seq, 119-byte RX. Then treat the verbose envelope as a future target.
Declare the verbose envelope a target v2 and state that current firmware does not implement it, with a migration plan for the parser, IDs, timestamps, status/error frames, and buffer changes.
Minimum corrections before I can accept a corrected revision:

One named wire family and version; no silent translation or aliasing.
START literal matching the implementation, or explicitly marked target-only.
Remove or mark proposed: STOP, VERIFIED status, status/error frames, START_BATCH, CONFIRM.
Omit or null unsupported identities/timestamps, with a target tag; do not fabricate measured_at, device_id, boot_id, sample_id, or seq.
Command frames within 119 content bytes, or an approved buffer-change decision (the current build has only 266 B SRAM free).
Profile/quantity/actor kept app/cloud-side keyed by batch_id.
Preserve the correct semantics: ACK is not physical proof; START ACK is receipt only; RUNNING is controller-reported, not independent relay-contact evidence.
The semantic direction in the provisional contract—invalid readings are null, timestamps are not invented, ACK is not Running—is sound and should be preserved. The wire format is what needs changing.
